# Code Review Fixes (v0.4.1, 2026-09-26) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fix the 15 defects found in the 2026-09-26 review of GuiInteraction — one that silently changes the bytecode level of every published artifact, two that crash on a null argument, one that corrupts the changelog on the next release, and eleven build/CI/packaging/process gaps — without changing the public API shape.

**Architecture:** Runtime fixes follow the pattern established by the 2026-09-25 plan: the faulty expression is extracted into a small package-scope static helper on the class that owns it, and that helper is unit-tested directly. This is required, not stylistic — `gi-swing` and `gi-fx` run their tests with `java.awt.headless=true` and both `InOut` constructors throw `UnsupportedOperationException` when headless, so no instance method of those classes is reachable from a test. `gi-common` and `gi-console` fixes are tested through their existing instance-level test classes. Build fixes are verified by running the affected Gradle task and inspecting its output; the shell-script fix is extracted into a sourceable library so it can be exercised against a fixture.

**Tech Stack:** Groovy 5.1.3 (`@CompileStatic`), Java 21 toolchain, Gradle 9.6.1 multi-module, JUnit Jupiter 6.1.3, Apache Tika core 3.3.2, JavaFX 23.0.2 (compileOnly), GradleUp Shadow 9.6.1, Spotless 8.10.2, SpotBugs plugin 6.5.11 / engine 4.10.4, OWASP dependency-check 13.0.0.

**Spec:** The review findings are reproduced in the *Findings Index* below. There is no separate spec document; this plan and that index travel together.

## Review Focus

Input classes these findings imply that no fix naturally exercises. Each has a test assigned to the task that owns the code.

1. **`promptPassword` at EOF with no system console** — the fallback branch reads `sysin`, which returns `null`; a caller who pipes an empty stdin must get `null`, not a crash or an empty password. → Task 6.
2. **A `Matrix` built without a name** — `matrixName` is null, and the JavaFX tab title is built by string concatenation, so it renders `null (3 rows)` rather than a usable label. → Task 7.
3. **`shellCommand` on Windows with `ComSpec` unset** — the fallback to `cmd.exe` is the only thing standing between a stripped environment and a `NullPointerException` in `ProcessBuilder`. → Task 9.
4. **A release re-run for a version that was already written to the changelog** — `release.sh --skip` exists to resume a partial publish with the same version, and promotion leaves a fresh empty `## Unreleased` behind, so a second run must not promote that empty section into a duplicate heading. → Task 12.
5. **`release.md` with no `## Unreleased` section** — a release run straight after someone hand-edits the changelog must still produce a section, not silently write nothing. → Task 12.
6. **A version bash mishandles when bumping** — `bump_version` computes on the version fields, so a two-component version (`0.4`) bumps *silently* to a plausible wrong answer, because an empty field is `0` inside `$(( ))`, while a leading zero (`0.08.1`, invalid octal) aborts the run outright. Both land after the tag check has passed. → Task 13.

## Task 1: Apply the Java 21 toolchain to every subproject

**Closes:** Findings 1, 15 (version table)

The root `build.gradle` intends to force a Java 21 toolchain on every module. The guard it uses can never be true, so all four published modules compile with whatever JDK runs the Gradle daemon. On a JDK 25 daemon the project publishes class-file major 69 artifacts that no Java 21 consumer can load, while README and AGENTS.md promise "Any JDK 21+".

```groovy
/**
 * Resolves the OpenJFX platform classifier for the machine running the build and
 * exposes it as `javafxClassifier`.
 *
 * OpenJFX publishes one artifact per platform. Guessing wrong is not a build
 * failure but a runtime one: the wrong natives load and fail with
 * UnsatisfiedLinkError. macOS ships on both x64 and aarch64, so the architecture
 * has to be part of the decision, and an unrecognised platform must fail loudly
 * rather than produce an unresolvable 'unknown' coordinate.
 */

import org.gradle.internal.os.OperatingSystem

def currentOs = OperatingSystem.current()
def arch = System.getProperty('os.arch', '').toLowerCase(Locale.ROOT)
def aarch64 = arch in ['aarch64', 'arm64']
def x64 = arch in ['x86_64', 'amd64']

def unsupported = {
    throw new GradleException(
        "Unsupported platform for JavaFX: ${currentOs.name} (os.arch=${arch}). " +
        "Supported: Linux x64/aarch64, macOS x64/aarch64, Windows x64.")
}

// A JVM can only load natives built for its own architecture, and os.arch reports
// the JVM's architecture rather than the machine's. So every branch below picks the
// artifact matching os.arch or fails naming it: substituting the x64 build on an
// aarch64 JVM (or vice versa) is a guaranteed UnsatisfiedLinkError at runtime, never
// something emulation rescues.
String classifier
if (currentOs.linux) {
    if (aarch64) {
        classifier = 'linux-aarch64'
    } else if (x64) {
        classifier = 'linux'
    } else {
        unsupported()
    }
} else if (currentOs.macOsX) {
    if (aarch64) {
        classifier = 'mac-aarch64'
    } else if (x64) {
        classifier = 'mac'
    } else {
        unsupported()
    }
} else if (currentOs.windows) {
    // OpenJFX publishes only an x64 Windows build -- checked against Maven Central for
    // 23.0.2, where the classifiers are linux, linux-aarch64, mac, mac-aarch64 and win.
    // An Arm64 JVM cannot borrow it. On Windows on Arm an Arm64 process can load only
    // Arm64 binaries; x64 binaries load into x64 or Arm64EC processes. The emulator
    // runs an x64 *process* -- it does not let an Arm64 process load an x64 DLL.
    // See https://learn.microsoft.com/en-us/windows/arm/arm64ec#interoperability
    // os.arch reports the JVM's architecture, not the machine's, so the supported
    // route on an Arm64 machine is an x64 JDK: that process is emulated and reports
    // os.arch=amd64 here, which selects 'win' correctly.
    if (!x64) {
        throw new GradleException(
            "JavaFX publishes no ${arch} Windows build, and a ${arch} JVM cannot load the " +
            "x64 natives: on Windows on Arm an Arm64 process can load only Arm64 binaries. " +
            "Build with an x64 JDK instead -- it runs under emulation on Arm and reports " +
            "os.arch=amd64. See https://learn.microsoft.com/en-us/windows/arm/arm64ec#interoperability")
    }
    classifier = 'win'
} else {
    unsupported()
}

ext.javafxClassifier = classifier
```

- [ ] **Step 2: Write the library**

Create `release-lib.sh`:

```bash
#!/usr/bin/env bash
#
# Changelog and version helpers for release.sh.
#
# This file is meant to be sourced, not executed, so the functions can be
# exercised against a fixture without running a release:
#
#   source ./release-lib.sh
#   promote_unreleased_section 0.4.1 2026-09-26 /tmp/release.md

# True when the changelog already has a section for this version. Both writers
# below check it: re-running a release for the same version after a partial
# publish is an explicit workflow (release.sh --skip), and it must not add a
# second heading for that version.
release_section_exists() {
    local version=$1
    local file=${2:-release.md}
    [ -f "$file" ] && grep -qE "^## +${version//./[.]} - " "$file"
}

# Turn the curated "## Unreleased" section into a released one and open a fresh
# empty "## Unreleased" above it. The hand-written notes stay where they are,
# under the version they describe.
#
# Returns 0 when a section was promoted, 1 when the file has no Unreleased
# heading (the caller then falls back to insert_release_section), and 2 when the
# file already has a section for this version, so there is nothing to do.
promote_unreleased_section() {
    local version=$1
    local date=$2
    local file=${3:-release.md}
    local tmp

    if [ ! -f "$file" ]; then
        return 1
    fi
    if release_section_exists "$version" "$file"; then
        return 2
    fi
    if ! grep -qE '^## +Unreleased[[:space:]]*$' "$file"; then
        return 1
    fi

    tmp=$(mktemp)
    awk -v heading="## ${version} - ${date}" '
        !promoted && /^## +Unreleased[[:space:]]*$/ {
            print "## Unreleased"
            print ""
            print heading
            promoted = 1
            next
        }
        { print }
    ' "$file" > "$tmp"
    mv "$tmp" "$file"
}

# Insert a "## <version> - <date>" section built from commit subjects before the
# first existing "## " heading, or append it when the file has none. printf is
# used rather than echo -e so a commit subject containing a backslash survives.
#
# Returns 0 when a section was inserted and 2 when the file already has one for
# this version.
insert_release_section() {
    local version=$1
    local date=$2
    local commits=$3
    local file=${4:-release.md}
    local section tmp line

    if release_section_exists "$version" "$file"; then
        return 2
    fi

    section=$(mktemp)
    {
        printf '## %s - %s\n\n' "$version" "$date"
        if [ -n "$commits" ]; then
            printf '### Changes\n\n'
            while IFS= read -r line; do
                if [ -n "$line" ]; then
                    printf -- '- %s\n' "${line#* }"
                fi
            done <<< "$commits"
            printf '\n'
        fi
    } > "$section"

    if [ ! -f "$file" ]; then
        printf '# Gui Interaction Release Notes\n\n' > "$file"
    fi

    tmp=$(mktemp)
    awk -v section="$section" '
        !inserted && /^## / {
            while ((getline line < section) > 0) print line
            close(section)
            inserted = 1
        }
        { print }
        END {
            if (!inserted) {
                while ((getline line < section) > 0) print line
                close(section)
            }
        }
    ' "$file" > "$tmp"
    mv "$tmp" "$file"
    rm -f "$section"
}

# Reject a version the release machinery cannot handle before anything is mutated.
# Two shapes are dangerous, for opposite reasons. A two-component version fails
# quietly: an empty field is 0 inside $(( )), so "0.4" patch-bumps to "0.4.1" with
# exit status 0, and the wrong version then flows into the commit, the tag and the
# three-part regexes used for the README. A leading zero fails loudly: 08 and 09 are
# invalid octal to bash, which aborts release.sh mid-flight under `set -e`. Semantic
# versioning forbids leading zeros anyway.
validate_version() {
    local version=${1%-SNAPSHOT}
    if [[ ! "$version" =~ ^(0|[1-9][0-9]*)\.(0|[1-9][0-9]*)\.(0|[1-9][0-9]*)$ ]]; then
        echo "Unsupported version '${1}'. Expected MAJOR.MINOR.PATCH or MAJOR.MINOR.PATCH-SNAPSHOT, with no leading zeros." >&2
        return 1
    fi
    return 0
}
```

## Task 13: Validate the version before the release mutates anything

**Closes:** Finding 12 (the `bump_version` half)

`bump_version` splits the version on `.` and does arithmetic on the fields. Two shapes go wrong, in opposite ways, both after the tag check and part-way into the release:

- **`0.4` fails quietly.** An empty variable is `0` inside `$(( ))`, so a patch bump of `0.4` yields `0.4.1` and a minor bump yields `0.5.0` — exit status 0, no message. That wrong version then flows into the release commit, the tag and the published coordinates, and `check_readme_version` / `update_readme_version`, whose regexes are three-part, cannot match it. *(An earlier draft of this plan predicted `syntax error: operand expected` here. That was wrong; Step 1 below shows what bash actually does.)*

`validate_version` (added to `release-lib.sh` in Task 12) rejects both shapes up front, and `bump_version` is made base-10 explicit so the arithmetic is safe no matter who calls it.

- [ ] **Step 1: Add the changelog entries**

In `release.md`, under `## Unreleased`, append:

```markdown
- Fixed (build): the Java 21 toolchain was never applied to any module — the guard in the root `subprojects` block ran before the modules applied the `java` plugin, so every artifact was compiled at the Gradle JVM's language level. Modules now pin Java 21 through `pluginManager.withPlugin('java')`.
- Fixed (build): `./gradlew check` and `./gradlew build` skipped Spotless and SpotBugs entirely, because the configuration cache is on by default. Both now run as part of the default `check`; the workarounds they were disabled for are obsolete on Gradle 9.6.1.
- Fixed (build): the OWASP scan ran `dependencyCheckAnalyze` against the dependency-free root project and CI's `dependency-check` job ran `dependencyUpdates` instead of a scan. Both now use `dependencyCheckAggregate`, which covers all four modules.
- Fixed (build): the JavaFX platform classifier assumed aarch64 on every macOS and produced an unresolvable `unknown` on any other platform. A `se.alipsa.gi.javafx-platform` convention plugin now resolves `linux`, `linux-aarch64`, `mac`, `mac-aarch64` or `win` from the JVM's `os.arch`, and fails with the platform and architecture named for anything else — including an Arm64 JVM on Windows, where OpenJFX publishes no Arm64 build and an Arm64 process cannot load the x64 one. Build with an x64 JDK there.
- Fixed: console `display(String)` threw `NullPointerException` for a null file name; it now behaves like `display((File) null)` and reports the problem on stdout, matching `gi-swing` and `gi-fx`.
- Fixed: console `promptPassword` threw `NullPointerException` at end of input; EOF is now cancellation and returns `null`, like every other console prompt.
- Fixed: `view(Matrix)` threw `NullPointerException` for a null matrix in all three implementations, and a matrix built without a name rendered the JavaFX tab title as `null (3 rows)`; unnamed matrices are now titled `Table`.
- Fixed: `Viewer`'s copy-shortcut OS check used a locale-sensitive `toLowerCase()`, which misbehaves on a Turkish-locale JVM.
- Fixed (packaging): fat JARs contained eight duplicated `LICENSE`, `NOTICE`, `DEPENDENCIES` and `buildinfo.xml` entries. They are now merged into one entry each, keeping every bundled dependency's licence text.
- Fixed (release): `release.sh` wrote generated notes above the curated `## Unreleased` section instead of promoting it, mangled commit subjects containing backslashes through `echo -e`, skipped the changelog entirely when `build.gradle` already held the release version, and could fail mid-release on a version that was not `MAJOR.MINOR.PATCH`. The changelog helpers now live in the sourceable `release-lib.sh`.
- Added: `urlExists` logs the cause it swallows at debug level; the boolean contract is unchanged.
- Added: both branches of the platform shell command are unit-tested, and a `windows-smoke` CI job runs the `gi-common` and `gi-console` suites on Windows.
- Removed: the `gi-fx` `rowsForViewer` identity helper.
```
