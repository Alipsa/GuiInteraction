# Code Review Fixes (2026-09-25) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fix the 17 defects found in the 2026-09-25 review of GuiInteraction — three that corrupt published artifacts, six that crash or misbehave at runtime, and eight build/CI/docs gaps — without changing the public API shape.

**Architecture:** Every runtime fix extracts the faulty expression into a small package-scope static helper on the class that owns it, then unit-tests that helper directly. This is required, not stylistic: `gi-swing` and `gi-fx` run their tests with `java.awt.headless=true`, and both `InOut` constructors throw `UnsupportedOperationException` when headless, so no instance method of those classes can be tested. Helpers are pure, so they are testable without a display. `gi-common` and `gi-console` fixes are tested through their existing instance-level test classes. Build fixes are verified by running the affected Gradle task and inspecting its output.

**Tech Stack:** Groovy 5.0.8 (`@CompileStatic`), Java 21 toolchain, Gradle 9.6.1 multi-module, JUnit Jupiter 6.1.2, Apache Tika core, JavaFX 23.0.2 (compileOnly), GradleUp Shadow 9.6.1 (introduced in Task 2).

**Spec:** The review findings are reproduced in full in the *Findings Index* below. There is no separate spec document; this plan and that index travel together.

Replace the entire contents of `buildSrc/src/main/groovy/se.alipsa.gi.fatjar-conventions.gradle` with:

```groovy
/**
 * Convention plugin for creating fat JARs with all dependencies bundled.
 * Apply this plugin to any module that needs a fat JAR artifact.
 *
 * Usage in module build.gradle:
 *   plugins {
 *       id 'se.alipsa.gi.fatjar-conventions'
 *   }
 *
 * Produces a 'shadowJar' task publishing <artifactId>-<version>-fatjar.jar.
 * Shadow is used instead of a plain Jar task because it merges duplicate
 * META-INF/services entries; a plain Jar with DuplicatesStrategy.EXCLUDE keeps
 * only the first copy and silently drops every other service registration.
 */

plugins {
    id 'com.gradleup.shadow'
}

tasks.named('shadowJar', com.github.jengelman.gradle.plugins.shadow.tasks.ShadowJar) {
    archiveClassifier = 'fatjar'

    // REQUIRED for mergeServiceFiles() to do anything. ShadowJar's constructor
    // calls setDuplicatesStrategy(DuplicatesStrategy.EXCLUDE), so without this
    // line every service file after the first is dropped before any transformer
    // sees it, reproducing exactly the bug this task exists to fix.
    duplicatesStrategy = DuplicatesStrategy.INCLUDE

    // Union every META-INF/services/* file across the bundled jars.
    mergeServiceFiles()

    // Exclude signature files that cause issues when repackaging signed JARs
    exclude 'META-INF/*.RSA', 'META-INF/*.SF', 'META-INF/*.DSA'

    // INCLUDE writes non-merged duplicates once per source jar. Module
    // descriptors are the only ones that matter here: a fat JAR is not a module,
    // and duplicate descriptors make jar tooling warn.
    exclude 'module-info.class', 'META-INF/versions/*/module-info.class'
}
```

`DuplicatesStrategy` needs no import — it is in Gradle's default imports.

This configuration was validated against Shadow 9.6.1 on a standalone project depending on the same `ph-*` 12.1.0 jars: without `duplicatesStrategy = INCLUDE` the merged `ICleanUpRegistrarSPI` contained **one** entry (identical to today's broken jar); with it, all **five**, and with the `module-info` excludes, zero duplicate `.class` entries.

Note what is deliberately gone: the `tasks.named('jar') { dependsOn fatJarTask }` block. `jar` no longer builds the fat jar. Shadow wires `shadowJar` into `assemble` itself.

      }
    }

## Out of Scope

Noted during the review but deliberately not planned here. Raise separately if wanted.

- **Swing dialogs are not dispatched to the EDT.** `JOptionPane`, `JFrame`, and `JTable` are created on the calling thread. `GuiInteraction`'s class javadoc already states that UI operations are the caller's responsibility ("EDT for Swing, FX Application Thread for JavaFX"), and `gi-fx` dispatches internally while `gi-swing` does not. Making `gi-swing` symmetric with `gi-fx` is a behavioural change worth its own design discussion.
- **SpotBugs reports missing analysis classes** (`org.apache.tika.Tika`, `org.commonmark.ext.gfm.tables.TablesExtension`) when analysing `gi-swing` and `gi-fx`, because those are `implementation` dependencies of `gi-common` and so are absent from the dependents' compile classpath. Analysis still completes; widening `auxClassPaths` to include `runtimeClasspath` would silence it.
- **`Viewer.viewHtml` renders untrusted HTML in a `WebView` with JavaScript enabled**, and `webEngine.load` is chosen by `url.startsWith("http")`, which also matches content beginning with those four characters. A security-minded pass over the viewer belongs in its own change.
- **`new Tika()` is constructed per `getContentType` call** — already tracked as TODO 6.3.
- **`FileUtils.readXml` reads whole files into memory** with no size cap.
- **`promptPassword` returns a `String`** and does not clear the intermediate `char[]`, so the password stays in the heap until GC.
